# Olist E-Commerce Analytics | SQL & Power BI

An end-to-end portfolio project exploring Brazilian e-commerce sales, delivery performance, customer satisfaction and product trends using **MySQL, SQL, Power BI and DAX**.

> **Project status:** Portfolio case study based on historical Olist data. The visuals and KPIs summarize the imported local dataset; this is not a live production dashboard.

## Project at a glance

| Metric | Result |
| --- | ---: |
| Orders in dataset | 99,441 |
| Delivered orders | 96,478 |
| Delivered product sales (excluding freight) | **BRL 13.22M** |
| Items sold in delivered orders | 110,197 |
| Average order value (product sales / delivered orders) | BRL 137.04 |
| Late delivered orders | 7,826 |
| Late delivery rate | 8.11% |
| Average delay among late orders | 9.53 days |
| Average review score | 4.09 / 5 |
| Review records | 99,204 |

| Average rating — on-time deliveries | 4.29 / 5 |

*Counts, monetary totals and ratings are rounded/displayed as in the Power BI report. BRL denotes Brazilian real. Figures describe this historical dataset, not a current company performance claim.*

## Business questions

1. How much product revenue is generated by fulfilled orders, and how has it changed over time?
2. Which categories, states, sellers and products contribute most to sales?
3. What share of delivered orders arrive after their estimated date?
4. Where are delays and longer delivery times concentrated?
5. How does the customer review score differ between late and on-time deliveries?

## Key findings

- **BRL 13.22M** in product sales is associated with delivered orders (excluding freight).
- **8.11%** of delivered orders were late; when late, deliveries exceeded the estimate by **9.53 days on average**.
- Average review score was **2.57 for late deliveries** versus **4.29 for on-time deliveries**, a **1.72-point gap**. This is an association in historical data, not proof that delivery delay alone caused the lower score.
- Health & Beauty, Watches & Gifts, and Bed Bath Table were among the leading categories by product sales.
- São Paulo (SP) contributed the largest volume in several state-level views; counts and rates should be interpreted separately.

## Practical recommendations

1. Monitor late-delivery rates alongside absolute late-order counts to spot both high-risk and high-volume regions.
2. Prioritize delivery reliability where customer satisfaction is most affected.
3. Track monthly trends and investigate spikes before drawing causal conclusions.
4. Use product and category performance to prioritize commercial analysis; avoid overinterpreting highly rated categories with few reviews.

## Tools and workflow

**MySQL & SQL:** imported CSV tables, checked row counts, joined order/customer/item/product/review data, calculated order, revenue, late-delivery and rating KPIs.

**Power BI:** imported eight tables from local MySQL, defined relationships, created DAX measures, and built four report pages.

**Data model note:** order-level and item-level facts were analyzed at their appropriate grain to avoid inflating sales amounts through joins to repeated payment or review rows.

## How to explore

1. Download the [public Brazilian e-commerce dataset by Olist on Kaggle](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce).
2. Create a MySQL schema named `olist_analysis` and load the relevant CSV tables.
3. Review the SQL scripts in [`sql/`](sql/) for import examples and analysis queries.
4. Open [`Olist_Ecommerce_Analytics.pbix`](powerbi/Olist_Ecommerce_Analytics.pbix) in Power BI Desktop.
5. If needed, update the MySQL data-source path and credentials in Power BI Desktop. This PBIX was developed against a **local MySQL database**; a connection refresh will not work on a new computer until its MySQL data source is configured.

**Reproducibility note:** The SQL folder contains working-session scripts and examples, not a complete automated database setup or one-click ETL pipeline. Import scripts require dataset paths to be adapted to your environment. The public Olist CSV data is **not redistributed** in this repository.

## Scope and limitations

- The dataset is historical and educational.
- Review records are not necessarily unique orders; `Total Reviews` is a row count.
- A product rating filtered through item-level relationships can have a different analytical grain from an order-level rating. Interpretation of category ratings deserves care.
- Counts and values were checked against the project’s SQL results, but this portfolio report is not a production-grade validated financial system.
